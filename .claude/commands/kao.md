# КАО — «Запусти команду агентов»

Это определение и исполняемый плейбук цикла КАО (команда агентов-отладчиков).
Триггеры в чате: «запусти команду агентов», «запусти агентов», «КАО»,
«команда агентов». Запуск означает: прогнать полный цикл исчерпывающего
аудита и починки приложения до зелёного.

**Зона ответственности раунда:** `$ARGUMENTS`
— если зона не задана, аудируется **ВСЁ приложение** (включая мельчайшие нюансы,
демо «Watch Demo» и «Try Yourself», все элементы дизайна и UI/UX, security).

---

## Цикл из 3 фаз

### 1. Писатели тестов — 3 подкоманды, стартуют ОДНОВРЕМЕННО (параллельно)
Их находки сливаются в общий пул и передаются тестерам.
- **1.1 UI/UX** — интерфейс, расположение элементов, отсутствие overlapping,
  accessibility (ARIA / контраст / управление фокусом), соответствие мировым
  best-practices. Инструменты: Playwright E2E, visual regression, Lighthouse/Axe,
  Vitest + React Testing Library.
- **1.2 Functionality** — вся функциональность до мельчайших элементов; backend
  pytest + sandbox node-тесты + frontend vitest на бизнес-логику. На каждой
  итерации — полный обход, не только изменившееся.
- **1.3 Security** — ОБЯЗАТЕЛЬНО 4 класса:
  - **Auth/Authz** — JWT-валидация, ownership-чеки на каждом endpoint, отказ в
    доступе к чужим session/code_version (IDOR).
  - **Input validation / injection** — фаззинг полей; SQL, XSS, path traversal,
    iframe-sandbox escape.
  - **Dependency vulnerabilities** — `npm audit` + `pip-audit`, сверка с CVE.
  - **Secrets / config leaks** — `.env`, secret keys, токены не попадают в логи,
    API-ответы, frontend-bundle.

### 2. Тестеры
Гоняют **весь объединённый пул**, классифицируют находки —
**critical / serious / minor / suggestion** — и передают фиксерам.
Каждую находку проверяют **состязательно** (пытаются опровергнуть), оставляют
только независимо подтверждённые.

### 3. Фиксеры
Правят найденное. После фиксеров управление **снова уходит тестерам** —
независимая верификация (НЕ верим self-report фиксера) + проверка регрессий,
внесённых правками.

Цикл **Тестеры → Фиксеры → Тестеры** повторяется, пока тестеры не вернут
**0/0/0/0** (нуль critical, serious, minor И suggestion) в зоне раунда.

---

## Правила
- **0/0/0/0** — критерий завершения раунда.
- **Pre-existing проблемы** (не связанные с текущим раундом, либо крупные/рискованные
  рефакторы) — выносятся **отдельным task'ом, НЕ блокируют завершение**.
- Каждое исправление маркируется тегом **`КАО#<id>`** в коде И в сообщении коммита
  (чтобы можно было поднять историю «что нашёл и пофиксил КАО»).
- **Non-Degradation Rule** — ни одно изменение не должно молча сломать, убрать или
  ухудшить существующую функциональность; при неизбежном влиянии — предупредить
  пользователя и получить согласие до правки.
- Деплой на **stage** + независимая верификация. Коммит/пуш и раскатку на **prod**
  делать только по запросу пользователя; перед рестартом prod-бэкенда — проверить
  отсутствие живых сессий.

## Как исполнять (проверенная практика)

1. **Оркестровать многоагентным workflow** (Workflow tool). Раунд аудита:
   - Фаза **Audit** — ~8 параллельных аудиторов по измерениям (UI/UX ×2,
     Functionality+демо ×2, Security ×3, tests/typecheck ×1), каждый возвращает
     структурированные находки (title, severity, file, location, evidence,
     suggested_fix, confidence). Просить ТОЛЬКО реальные, подтверждённые кодом
     находки — точность важнее объёма.
   - Фаза **Verify** — состязательная проверка каждой находки отдельным агентом
     (пытается опровергнуть; можно дешёвой моделью). Оставить confirmed.
   - Фаза **Classify** — сгруппировать по severity.
2. **Фиксеры** — главный агент правит подтверждённое сам (надёжнее для точечных
   правок), тегирует `КАО#<id>`, деплоит на stage.
3. **Второй workflow-раунд (Тестеры)** — верификаторы независимо перепроверяют,
   что КАЖДЫЙ фикс реально устранил проблему, + ищут регрессии. Повтор циклов до
   0/0/0/0.
4. **Демо-рантайм** (Watch/Try, поведение в браузере: рендер, 0 ошибок консоли,
   главы/CTA/скорость/replay/full-window, Try→/login для анонима) проверять
   **ВЖИВУЮ** через браузер — субагенты этого не умеют.
5. По завершении: краткий отчёт (что нашли/пофиксили по классам, что вынесено
   отдельными задачами), затем по запросу — коммит (`КАО#R<N>`), push, prod.
